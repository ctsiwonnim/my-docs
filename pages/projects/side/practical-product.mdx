# Practical Product — 패션 커머스 플랫폼

**형태** 팀 프로젝트 (2인) · **담당 파트** 회원 · 인증 · 인프라/배포

## 개요

무신사 스타일에서 영감을 받은 패션 커머스 서비스로, 화면 디자인보다 결제·재고·인증처럼 실무에서 자주 부딪히는 문제를 직접 풀어보는 데 초점을 맞춘 프로젝트입니다. Spring Boot 기반 모듈러 모놀리식 구조로 회원, 카테고리, 상품, 주문, 결제 도메인을 물리적으로 분리하되 단일 애플리케이션으로 배포해, 마이크로서비스의 운영 복잡도 없이 도메인 응집도를 확보했습니다.

## 담당 역할 (회원 · 인증 · 인프라/배포)

- httpOnly 쿠키 기반 JWT 인증 구현
- 리프레시 토큰 서버 측 무효화 — 로테이션 + 재사용 탐지 (탈취된 토큰 재사용 시 즉시 세션 무효화)
- 리프레시 토큰 소비 시 비관적 락으로 동시 요청 경합 차단
- 인증 관련 CSRF 방어, 쿠키 secure 옵션 fail-safe 기본값 적용
- Docker 이미지 빌드 → Docker Hub 푸시 → EC2 배포 파이프라인 구성
- GitHub Actions 기반 CI/CD 구축, `deploy` 브랜치 배포 트리거 관리
- PR마다 빌드/테스트를 자동 실행하는 코드 리뷰 봇 연동

## 서비스 주요 기능 (팀 전체)

- 카테고리 기반 상품 탐색, SKU 단위 재고 관리
- 재고 예약(원자적 차감) 기반 주문 생성으로 동시 주문 시 초과 판매 방지
- 토스페이먼츠 연동 결제 승인, 가상계좌 입금 웹훅을 Outbox 패턴으로 안전하게 처리
- Prometheus/Grafana/Loki/Tempo 기반 관측성 대시보드, 결제 실패율 등 주요 지표 Discord 알림

## 기술 스택

- Backend: Java, Spring Boot, Gradle 멀티모듈, MySQL
- 인증/보안: JWT, httpOnly Cookie
- 결제: 토스페이먼츠(Toss Payments)
- Frontend: Next.js 16 (App Router), React 19, TypeScript, Tailwind CSS v4
- DevOps: Docker, GitHub Actions, EC2

## 트러블슈팅

**리프레시 토큰 보안**: 단순 저장 방식은 토큰 탈취 시 무제한 재사용이 가능하다는 문제가 있어, 토큰을 사용할 때마다 새 토큰으로 교체(로테이션)하고 이미 사용된 토큰이 재사용되면 즉시 해당 세션을 무효화하는 재사용 탐지 로직을 적용했습니다. 또한 토큰 소비 시점에 비관적 락을 걸어 동시 요청으로 인한 경합을 차단했습니다.
